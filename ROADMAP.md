## Planning rules

1. The `.github` milestone issue is the organization-level source of truth.
2. Each milestone is outcome-based, not a feature bucket.
3. Repository work exists only when it contributes directly to the milestone outcome.
4. Scope should be reduced before the target outcome is delayed.
5. Screenshot Studio is the primary owned product surface; infrastructure repos should remain replaceable wherever practical.
6. BetterShot and Mike are not part of the active roadmap.
7. LinkPreview is expected to be absorbed as a capability rather than remain a standalone product.
8. Wanta becomes a stronger product dependency only if a dedicated founder/operator shell is validated.
9. If a fork later enables GitHub Issues and needs detailed implementation tracking, repo issues should link back to the canonical org milestone rather than creating a second roadmap.

## Phase structure

**October 2026 – March 2027:** Own launches.  
**April – June 2027:** Own founder context.  
**July – October 2027:** Own execution.
